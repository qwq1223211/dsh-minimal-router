## 一、我为什么要装这个？

DSH 默认会把**所有**插件的工具说明一次性塞给模型。装了几十个插件之后，模型每一轮都要先"读一遍"上百个工具的说明书——哪怕这一轮只是在聊天。

### 三组实测数字（同一台机器、同一个模型）

**① 工具：165 → 69**

| | 装之前（auto） | 装之后（core 阶段） |
|---|---|---|
| 发给模型的工具数 | **165 个** | **66 个**（−60%） |
| 工具说明的字节数 | **131,694** | **43,238**（**−67.2%**） |
| 每轮 promptTokens（纯净新会话实测） | 47,885 | **25,688**（**−46.4%**） |
| 缓存命中率 | 91.4%（第 2 步） | **99.16%** |
| 切换阶段的一次性代价（小会话） | — | 约 3 千 token |
| 切换阶段的一次性代价（**50 万 token 的大会话**） | — | **51 万 token 全价** ⚠️ |

> 这组数字来自一个**全新的、干净的会话**（只有一个系统提示、没有历史包袱），是这套方案能达到的真实上限。

**切换一次，聊一轮就赚回来（约 10 倍）。**

**② 系统提示：159,334 → 17,685**

这个是我踩过的最大一个坑：

| 情况 | 系统提示字节 | 说明 |
|---|---|---|
| 一个聊了很久的旧会话 | **159,334** | 系统提示被追加了 **9 份**（每改一次记忆/装一次插件就 +1 份 17,685） |
| 一个干净的新会话 | **17,685** | 只有 1 份 |

**结论：开新会话省下的，比这个插件省下的还多。** 这两件事要一起做。

**③ 缓存命中：冷启动 0% → 第二步 91% → 稳定 99%+**

| 第几步 | promptTokens | 命中率 |
|---|---|---|
| 新会话第 1 步（冷启动） | 43,864 | 0% |
| 新会话第 2 步 | 47,885 | 91.42% |
| 稳定后 | — | 99%+ |

**冷启动必然是 0%，这是物理规律，不用在意。** 看趋势，别看第一次。

> 老实说一句：省下来的 token 里大部分是"缓存命中"的便宜 token，所以账单上的数字不会像字节数那么夸张。但它是**持续**省的，而且顺带解决了"模型看着一堆工具发呆、乱选工具"的问题。

## 二、装一次，得到三个模块、九个工具

**一个包，一次安装，一次重载。** 你不用分三次装三个插件——因为**每装一次插件就要重载一次，而每次重载都可能触发一次全量前缀重建**（实测最贵的一次 51 万 token）。

| 模块 | 工具 | 作用 |
|---|---|---|
| **路由**（主角） | `route_stage` `route_status` `route_reset` `route_init` | 分阶段、物理砍工具、切阶段 |
| **熔断** | `guard_status` `guard_reset` | 连续 3 次工具失败就中断，防止死循环烧钱 |
| **探针** | `cache_probe_report` `cache_probe_clear` | 记录每次请求的真实 token 账单，用来验证省钱效果 |

**不想用某一块？** 一行配置关掉，不用拆包：

```yaml
guardEnabled: false   # 关掉熔断
probeEnabled: false   # 关掉探针
```

> 强烈建议**保留探针**：没有它你没法验证到底省了多少，也没法发现"某次操作把缓存打爆了"。

### 路由模块的四个工具

| 工具 | 干什么 |
|---|---|
| `route_stage("core")` | 切换当前任务阶段 |
| `route_status()` | 看现在是哪个阶段、砍掉了多少工具 |
| `route_reset()` | 一键复位，解除所有限制 |

**最重要的一条：它们永远不会被拦截。** 哪怕你被阶段规则卡住了，这三个工具也永远能用——这是刻意的"逃生门"设计。

## 三、它是怎么工作的（30 秒看懂）

1. **自动分类**：它按工具名的前缀自动打标签，不需要你配置。
   `unity_object_create` → 属于 `unity` 组
   `mcp__meshy__meshy_image_to_3d` → 属于 `meshy` 组
   `read` / `write` / `pwsh` → 属于 `core`（基础工具，永远在场）
2. **判断阶段**：你说的话里出现"界面/按钮"→ 切到 `unity-ui`；出现"贴图/模型"→ 切到 `art`。
3. **物理瘦身**：切到某个阶段后，不属于这个阶段的工具会被**真的从请求里摘掉**，不是只提示。
4. **粘住**：切一次就一直是这个阶段，**不会因为你说下一句话就失效**（只有再命中别的关键词、或你手动复位，才会变）。

## 四、默认有 6 个阶段

| 阶段 | 允许的工具组 | 说这些话会自动切过去 |
|---|---|---|
| `auto`（默认） | 全部，不限制 | —— |
| `core` | 只有基础工具 | 通用、基础、core |
| `unity-code` | unity + 13 个 Unity 子系统 | 代码、脚本、编译、报错、unity |
| `unity-ui` | unity、ui、uikit、uiflow、dialogue、quest | 界面、按钮、布局、面板 |
| `art` | art、meshy、image、asset | 贴图、模型、素材、美术 |
| `audio` | audio | 音效、音乐 |

> `auto` 是默认值，**不砍任何工具**，所以刚装完你不会感觉到任何限制。只有进入具体阶段才会开始瘦身。

## 五、我不是做 Unity 的，怎么改成我自己的领域？

这正是它设计成"通用"的原因：**阶段和标签都写在配置里，不用改代码。**

### 步骤 1：看看你现在有哪些工具组

对 AI 说：

> 调 route_status 看看

返回里有一个 `tagCounts`，长这样：

```json
{
  "unity": 26, "asset": 6, "audio": 3,
  "mcp": 1, "terminal": 6, "session": 5,
  "read": 1, "cache": 2, "route": 3
}
```

每个数字就是"这个前缀下有几个工具"。

### 步骤 2：编一个你自己的阶段表

打开插件目录下的 `cordis.patch.yml`，把 `stages` 加进去（示例：一个做 Python 数据分析的人）：

```yaml
- insert:
    - id: minimal-router
      name: '@local/dsh-minimal-router'
      config:
        defaultStage: auto
        enforceByRestrict: true
        stages:
          auto:
            title: 自动
            allow: []
            keywords: []
          core:
            title: 通用
            allow: []
            keywords: ['聊天', '通用']
          python:
            title: 写 Python
            allow: ['python', 'notebook', 'jupyter']
            keywords: ['python', '脚本', 'pandas', '数据清洗']
          data:
            title: 数据分析
            allow: ['sql', 'db', 'chart', 'plot']
            keywords: ['报表', '图表', '数据库', 'sql']
          writing:
            title: 写文档
            allow: ['office', 'docx', 'pptx', 'xlsx']
            keywords: ['报告', '文档', 'ppt']
```

**规则就三条：**

- `allow` 里写**工具名前缀**（`python_` 开头的工具就写 `python`），不用写全名
- `keywords` 里写你会说的话，中文英文都行
- 阶段表里**前面**的优先匹配，所以把更具体的放前面

改完在「设置 → 插件」里把这行**关掉再打开**，立即生效。

### 为什么不怕"新装的插件没被分类"？

因为有个保护规则：**没被任何阶段认领的标签，永远放行。**

你新装一个 `foobar` 插件，它的标签 `foobar` 没人认领 → 任何阶段都能用 → **绝不会因为它没分类就把你拦死**。等你确认要管它了，再把 `foobar` 写进某个阶段的 `allow`。

## 五之二、⚠️ 降级保护（开源版的生命线）

这个插件的省钱效果依赖模型的一个能力：**系统提示的变更可以追加到历史尾部，而不是重写头部**。

不是所有模型都支持。已知情况：

| 模型 | 支持 | 结果 |
|---|---|---|
| `deepseek-flash` | ✅ `in-history` | 全功能 |
| `deepseek-v4-pro` | ❌ 只有 `leading-only` | **自动降级** |
| 其它任何没见过的模型 | ？ | **自动降级**（不确定就不冒险） |

**为什么必须降级：** 如果模型不支持，系统提示每变一次就要重写整个前缀 → 每一步的缓存全部失效 → 400K/步 全价 × 几十步，账单直接失控。

降级后会发生什么：

| 功能 | 安全模型 | 降级时 |
|---|---|---|
| 尾部路由提示 | ✅ 开 | ❌ **一个字都不注入** |
| 物理瘦身（restrict） | ✅ 开 | ❌ **强制关闭** |
| 越界拦截 | ✅ 开 | ✅ **保留**（不碰 prompt，零成本） |
| 死循环体检 | ✅ 开 | ✅ **保留** |

同时控制台会打一个醒目的警告框（同一个模型只打一次，不刷屏）：

```
╔════════════════════════════════════════════════════════════════╗
║ ⚠ dsh-minimal-router 已自动降级                                 ║
║                                                                ║
║ 当前模型：deepseek-account / deepseek-v4-pro                    ║
║ 原因：模型 deepseek-v4-pro 的 systemPromptUpdate 是             ║
║       "leading-only"（不是 in-history），系统提示一变就会重写前缀 ║
║                                                                ║
║ 已关闭：尾部路由提示、物理瘦身（restrict）                        ║
║ 仍保留：越界拦截、死循环体检（这两项不碰 prompt，零缓存成本）      ║
║                                                                ║
║ 确实知道风险还想开：config 里设 unsafeForce: true                ║
╚════════════════════════════════════════════════════════════════╝
```

### 我用的不是 DeepSeek，怎么办？

两个开关，任选其一：

```yaml
# 1) 精确放行：只信任你确认过的模型名（推荐）
trustedModels: ['my-flash', 'qwen-coder-plus']

# 2) 一刀切：全部强行开启（自担风险）
unsafeForce: true
```

**怎么知道自己的模型支不支持？** 换上去跑两步，然后用 `dsh-cache-probe` 看 `hitRate`：
- 一直 99%+ → 支持，可以加进 `trustedModels`
- 每步都掉到很低 → 不支持，别加

## 五之三、🛡 安全闸门（超长会话的刹车）

在很长的会话里切阶段，代价不是"省一点"，而是**把整个前缀按全价重算一遍**。实测：

| 会话大小 | 切一次阶段的代价 |
|---|---|
| 5 万 token | 约 3 千 token（便宜，随便切） |
| **50 万 token** | **约 51 万 token 全价（一次 1000 倍）** |

所以插件内置了闸门：**当上一次请求的上下文超过 `contextGuardThreshold`（默认 100,000 token）时，切阶段会被拒绝**，并告诉你原因和三条出路（开新会话 / 用 `force:true` / 别切）。

**闸门拦两条路，缺一条都等于没装：**

1. `route_stage` 工具显式切换
2. **关键词自动切换**（`agent/inbox/claimed`）—— 这个是我实测漏掉、后来补上的。漏网的后果是：用户在 78 万 token 的会话里随口说一句"切到 core 阶段"，直接触发 51.4 万 token 全量重建。

**我们拦不住的事**：DSH 的插件热重载（那是插件管理器的行为）。所以长会话里**别装插件、别改插件**，要动就开新会话。

## 六、三个铁血规则（不是配置项，改不了）

| 规则 | 说明 |
|---|---|
| **死循环体检** | 写文件前本地扫描代码。发现 `while(true)` / `for(;;)` / `do{}while(true)` **且循环体里没有 break/return/throw** → 直接拒绝写入，并告诉你在第几行。正常代码、注释里的、字符串里的、`grep "while(true)"` 都不会被误杀 |
| **越界拦截** | 在 `core` 阶段调 `meshy_*` 会被拦，并明确告诉你 `请立即调用 route_stage("art")` |
| **逃生门** | `route_*` / `guard_*` 永远放行，任何情况都不会把你锁死 |

## 八、常见问题

**Q：会不会把我卡住？**
不会。三个逃生门工具永远可用；最坏情况下在「设置 → 插件」里关掉这个插件，限制立刻全部消失（不用重启）。

**Q：会不会改我的文件？**
不会。它只做两件事：往上下文尾部加一行不超过 200 字的提示；在工具执行前做检查和拦截。

**Q：为什么我的模型换成别的会不一样？**
`deepseek-flash` 支持"系统提示追加到历史"这种机制，所以尾插几乎不破坏缓存。换成不支持它的模型时，这个插件会**自动降级并大声警告**（见下方"降级保护"）。

**Q：`promptTokens` 怎么还是几十万？**
那是**你的对话历史**，不是工具。开关插件前后对比 `toolsChars` 才说明问题。历史长了就会被压缩（compaction），那是另一个话题。
