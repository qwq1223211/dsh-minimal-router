# dsh-minimal-router · 开发总结（视频素材版）

> 所有数字都来自本项目真实探针记录 / 真实测试，不是估算。
> 标注「n=1」的地方是单一案例，不能当统计结论用——视频里请照实说。

---

## 0. 一句话版本

**我给 AI 装了 165 个工具，它每轮都要先把这 165 份说明书重读一遍——哪怕我只是在跟它聊天。**
这个插件做的事：让它只看见这一轮真正需要的工具，同时**保证它不会因此变傻、也不会锁死**。

---

## 1. 到底解决什么问题（人话版）

大模型每次回答之前，都要"读一遍"整段上下文。上下文里最肥的一块不是你的话，是**工具的说明书**——
每个插件装进来，都带着几百到几千字的参数说明，而且**每一轮都要重发**。

- 装 40 多个插件之后：**165 个工具、131,694 字节**的说明书，每轮都发一遍
- 这些说明书在讲什么，跟"帮我改个错别字"这件事**毫无关系**

所以第一版思路很朴素：**按任务分阶段，只给它这一阶段该用的工具。**

## 2. 三次被打脸（这是视频最值钱的部分）

### 2.1 第一次：我以为"切阶段"很便宜

我的假设是：切阶段只是换了工具列表，缓存大部分还在，最多损失一点点。

**实测**（780 条消息的会话，一次关键词触发的切换）：

```
messages 780 | tools 170 → 70 | promptTokens 520,129
新增全价 513,857 | 命中率 1.21%
```

**一句"切到 core 阶段"，把 51 万 token 的前缀全部按全价重算了一遍。**

而同样的事在**小会话**里只要 **3,205** token。
同一动作，差了 **160 倍**——这本身就说明我的模型是错的。

**所以加了安全闸门**：上下文超过 10 万 token 时，切阶段会被拒绝，除非显式 `force: true`。

**然后我发现自己犯了个更蠢的错**：第一版闸门只拦了 `route_stage` 工具调用，
**没拦"关键词自动切换"**那条路——于是用户在 78 万 token 的会话里随口一句话，照样触发了一次 51.4 万的全价重建。

> **闸门漏了一条路，等于没装。**

### 2.2 第二次：我以为成本可以预测

我打算"检查缓存热度，热的时候就别切"。听起来很合理。
于是我扒了自己 615 条探针记录，找出 60 次真实的前缀变化。

**结果是双峰的：**

| 类型 | 次数 | 这次未命中占上下文的比例 |
|---|---|---|
| 便宜档 | 35 | **0.2% ~ 1.2%** |
| 灾难档 | 11 | **98% ~ 99%** |

而且**成本和"改了多少"几乎无关**：

| 改了什么 | 花了多少 |
|---|---|
| 工具声明改了 **98,778** 字节 | **708** token |
| 工具声明只改了 **481** 字节 | **581,830** token |

**平均值 46.5%——对双峰分布取平均，毫无意义。**

结论：**便宜是运气，贵是风险。** 所以我放弃"精确预测"，改成**按最坏情况估**
（整段上下文全价），然后算一笔账：

```
最坏成本 ÷ 每轮省下的 token = 需要几轮才回本
```

回本超过 3 轮就不自动切。这个办法不优雅，但它**不会赌输**。

### 2.3 第三次：我以为提示是帮忙，A/B 显示它在害人

我在上下文尾部放了一行提示，告诉模型"你现在在哪个阶段、能用哪些组"。

为了验证它有没有用，我做了个对照实验：**两个全新会话，完全相同的任务，唯一差异是有没有那行提示。**

| | 无提示（臂 B） | 有提示（臂 A） |
|---|---|---|
| 调用被禁用的工具 | **调了** | **没调** |
| 收到什么 | 【阶段越界】+ 精确到工具名、当前阶段、允许组、以及该调哪个工具的修复指令 | —— |
| 结果 | 切阶段 → 重试 → **成功** | **直接放弃**："不在我的工具清单里" |

**原因**：我的提示里写着 `禁止组=audio,dialogue,enemy,gameplay,l10n,level,lighting,perf 等15组`——
因为超过 8 个就截断，而 `unity` **正好被压缩进了"等15组"**。
模型看到"这么一堆都不许用"，判定做不到，就停了。

而**没有提示的模型直接去试**，拿到的是精确到"请立即调用 route_stage('unity-code')"的拒绝信息。

> **提示在跟拒绝信息竞争，而且它输了。**
> 一条被截断的禁列清单，比沉默更糟。

**修法**：提示里**不再列禁止组**，只留可用组 + 一个永远正确的逃生动作 `route_stage("auto")`。
长度从 193 字降到 68~85 字。

> ⚠️ **诚实标注**：这是 n=1，每臂只跑了 1 次。它足以说明"旧文案**可能**让模型放弃"，
> **不足以**得出"有提示会让成功率下降 X%"。所以我把它做成了一个工具（`route_hint`），
> 让任何人都能在自己机器上跑更多轮。

## 4. 我踩过的坑（按类型分，这是"技术含量"最集中的部分）

### 4.1 平台 / 工具坑

| 坑 | 后果 | 教训 |
|---|---|---|
| **用 PowerShell 正则替换改 UTF-8 文件** | 文件被当 GBK 读写，中文全变乱码 + BOM，`SyntaxError`。**这坑我踩了两次** | **永远不用 PowerShell 做文本内容的读写替换**，用编辑工具 |
| `Copy-Item README.en.md README.md` 同步文档 | 把另一个文件里**没有的徽章**覆盖没了，GitHub 首页缺徽章一周 | 同步前先确认源文件是"全的那个" |
| `Get-Content` 显示中文乱码 | 只是控制台显示问题，文件其实是好的 | 用 `JSON.parse` / node 读一遍再判断，别信眼睛 |
| DSH 会话日志是多帧 zstd | `zstdDecompressSync` 只解第一帧，只读到 950 帧里的 1 帧 | 按 magic `28 b5 2f fd` 切分再解 |

### 4.2 接口 / 契约坑

| 坑 | 后果 | 教训 |
|---|---|---|
| 在插件全局 `ctx` 上调 `tools.restrict()` | 直接抛错：`requires a scoped context (agent.ctx)` | **DSH 明确禁止一刀切所有会话**，必须挂到具体会话 |
| `inject: ['tools','systemPrompt']` | 任何没有 `systemPrompt` 的环境，**整个插件加载失败**——连熔断和探针一起死 | 可选服务要自己 `ctx.get()`，不要写进 `inject` |
| `schemas()` 不反映 `restrict()` | `route_status` 报 153 个工具，实际只有 35 个 | 只有一个数据源是可信的：探针记录的 `tools` 字段 |
| `restrict()` 顺序反了 | 先读 `schemas()` 再 dispose 旧的，读到的是已砍过的列表，切回大阶段工具永远回不来 | **先拆旧限制，再算新列表** |
| 别的插件也在 `pre-execute` 上做决定 | 如果我返回 `allow`，会盖掉别人的拒绝 | 放行时必须 `next()` 往下传 |

### 4.3 逻辑坑

| 坑 | 后果 | 教训 |
|---|---|---|
| 安全闸门只拦了工具调用，没拦关键词 | 一次 51.4 万 token 的全价重建 | **多想一条"还有哪条路能触发同样的事"** |
| `while(true){}` 没被拦 | 最小扫描长度设成了 20，短循环直接跳过 | 改成 8 |
| 递归永远不告警 | 我把 `return` 当成了"退出条件"——但 `return f()` 正是递归 | 退出条件只认 `if / throw / switch / catch` |
| 关键词 `ui` 匹配到了 `uikit` 里面 | 误判阶段 | ASCII 词边界：`(?<![a-z0-9])kw(?![a-z0-9])` |
| 显式切了阶段，下一条消息就丢 | "切一次只能用一轮" | **粘住（sticky）**：没新信号就保持当前阶段 |
| 重复声明 `const stages`，还 `delete` 了一个 const | ESM 直接语法错误 | — |
| JSDoc 里套了块注释 | `SyntaxError: Unexpected token '}'` | 注释里不要嵌套 `/* */` |

### 4.4 设计坑（最值得讲的一类：**"装了但没效果"且不报错**）

| 坑 | 后果 |
|---|---|
| **运行时数据写在包目录里** | `link` 安装没事；真实依赖安装时包在 `node_modules/.pnpm/<hash>/`，**升级就清空**。已搬到 `~/.dsh/minimal-router/` |
| **探针工具没进逃生门白名单** | 一开 `strict: true`，把**诊断工具自己**藏了 → 从此看不到任何数字解释"为什么没省" |
| **`trustedModels` 按纯模型 ID 比较** | 配置写成 `bailian/deepseek-v4.1-flash-1017` 永远不命中，用户以为开了，其实还是降级态 |
| **`custom_stages.json` 只认对象写法** | 用户很自然会写成数组 `[{ "stage": ... }]` → **整份文件被静默忽略** |
| **阶段表和实际工具对不上** | 内置表认领的是 unity/art，某台机器只有 QQ 工具 → deny 永远是空 → **看起来装了，0 收益，且不报错**。现在有 `stageTableUnused` 直接告诉你 |
| **匿名 agent 共用 `__global__` 状态槽** | 两个窗口会互相覆盖：A 切阶段把 B 的工具砍了 |
| 关键词命中的"随机"太大 | 用户顺嘴提一句"界面"就切阶段 | 加了**迟滞（连续 2 次）+ 冷却（120 秒）** |

### 4.5 测试坑（这几条最容易被忽略）

| 坑 | 后果 |
|---|---|
| **假工具太"瘦"**（只有 name 没有 description） | 成本闸门算出来"能省 0.0 字节"，回本要 444 轮，把 4 个**无关**测试一起拦了 |
| **旧测试写死了旧行为** | 加了迟滞后，2 个测试"失败"——**这是测试在正确工作**，改测试而不是改回代码 |
| 断言写太窄 | 合并三个插件后，"只有 1 个监听器"的断言全挂 |

## 5. 安装（三种方式，选一个）

> **这一节可以直接做成演示录屏。**

### 方式 1 · 在 DSH 里直接喊话（推荐，小白用这个）

对 AI 说：

```
帮我安装这个插件：https://github.com/qwq1223211/dsh-minimal-router
```

### 方式 2 · 终端

```bash
dsh plugin --profile desktop add github:qwq1223211/dsh-minimal-router
```

（本质是把参数转发给 profile 目录里的 pnpm；装完如果列表里没出现，让 AI 把 bundle 启用一下）

### 方式 3 · 装不上就用这个兜底

```bash
git clone https://github.com/qwq1223211/dsh-minimal-router.git
```

然后把**文件夹的绝对路径**发给 AI：

```
用 plugin_manager install_bundle 安装这个目录：<你 clone 下来的绝对路径>
```

### ⚠️ 装完必须做这一步，否则等于没装

> **设置 → 插件 → 把「极简路由器」关掉，再打开。**
>
> link 安装不会热更新。不做这一步，跑的还是旧代码——你会以为"装了没效果"。

### 验证

对 AI 说：

```
调 route_status
```

能看到包含 `stages` / `tagCounts` / `modelGuard` 的 JSON 就是好了。

### 数据放在哪

`~/.dsh/minimal-router/`（探针历史、你自己的 `custom_stages.json`）。
**不在插件目录里**——因为真实依赖安装时，插件目录会被升级替换掉。

## 6. 它不做什么（诚实的边界，视频里一定要讲）

1. **不省系统提示。** 系统提示的大头来自会话长度和你用不上的 MCP。实测：旧会话里系统提示被追加了 **9 份**（159,334 字符），新会话只有 **1 份**（17,685）。**开新会话比装这个插件省得多。**
2. **不保证账单一定降。** 省的是 token，而且省下来的 **99.9% 是缓存价**的 token。想确认请自己看探针的真实数字。
3. **不改 DSH 源码。** 全部走公开接口。
4. **只管"事前削减"，不管"事后压缩"。** 长会话真正的大头是历史消息，请用 `/trim` 或 compaction 类插件。
5. **和另一个工具路由器不能同时开。** 两个都在收窄工具面，行为不可预测。

## 8. 评论区预判问题

**Q：省的是真钱吗？**
A：省的是 token，而且大部分是缓存价 token，账单变化没有字节数那么夸张。真数字请看探针 `cache_probe_report`。

**Q：我不用 Unity，能用吗？**
A：能。`route_init({"preset":"python-data"})` 直接写出可用配置（还有 web-dev / writing / qq-chat）。或者用 `route_use({"groups":[...]})` 临时收窄，**连阶段表都不用配**。

**Q：会不会把我的工具藏了导致它变傻？**
A：三层保险：① 逃生门（`route_*` / `guard_*` / 探针工具）硬编码永不拦；② 未知工具默认放行；③ 算不清就放行、缺服务就降级、出异常就把决定交给下一个插件。最坏情况关掉插件，限制立刻消失。

**Q：为什么不做"每轮调用小模型判断需要哪些工具"？**
A：那是每轮多一次请求，整段上下文按全价重发。省下的是便宜 token，花出去的是全价请求——净亏。所以判断权交回给**本来就在上下文里的模型自己**（`route_use` 工具，零额外成本）。

**Q：现在多大了？**
A：零依赖，8 个版本，214 项测试，ubuntu/macos/windows × Node 20/22 全绿。
